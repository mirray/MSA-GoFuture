1. Обеспечение качества данных с использованием ML
   - сервисы общаются с ML через строго типизированные контракты, например Protobuf. Чтобы исключить глюки нейронки
   - ограничение диапазонов данных, например коэффициент цена на км не может быть меньше 0, или более 100 условных рублей
   - контроль смещения данных - резкий скачок предполагает некорректную работу ML - отслеживание средних показателей за последние 5-10 минут и сравнение с текущими показателями. Например цена не может взлететь в 2-3 раза за 5 минут
   - трассировка сообщений - все ивенты должны иметь Trace_Id чтобы можно было отследить всю цепочку сообщений в случае некорректных данных
